# Aincrad Launcher

## 1. What is Aincrad Launcher?

Aincrad Launcher is a modern Minecraft: Java Edition launcher focused on performance, modularity, customization, and a great user experience.

The project is also intended to serve as a long-term software engineering learning experience, allowing its development to evolve alongside the developer's technical skills.

---

## 2. Why does this project exist?

I have always loved both Minecraft and software development, so I decided to combine these two interests into a single project.

Aincrad Launcher was created as a way to study software development and software engineering by building a real, complex product from the ground up.

The goal is not only to build a launcher, but also to learn from the entire development process.

---

## 3. What problem does it intend to solve?

Aincrad Launcher is not being created because existing Minecraft launchers are necessarily bad or incomplete.

The main motivation is to build my own interpretation of what a modern Minecraft launcher could be, while exploring different approaches to user experience, customization, architecture, and extensibility.

---

## 4. Who is the target audience?

The long-term goal is for Aincrad Launcher to be useful to a broad range of Minecraft: Java Edition players.

This includes:

- Casual players
- Advanced players
- Modded Minecraft players
- Players who manage multiple instances or profiles
- Users who value customization and a modern user experience

The initial versions, however, will primarily focus on creating a solid foundation before expanding to a broader audience.

---

## 5. What is the value proposition?

Aincrad Launcher aims to provide a modern Minecraft launcher with a strong focus on user experience and customization.

One of its distinguishing characteristics will be its visual identity, inspired by anime culture, while still keeping the application usable and accessible to users who are not necessarily interested in anime.

The goal is to provide a launcher that feels modern, customizable, responsive, and enjoyable to use.

---

## 6. What are the main goals of the project?

Aincrad Launcher is an ambitious long-term project.

The main goals include:

- High performance
- Modern and responsive user experience
- Instance management
- Profile management
- Mod and modpack support
- Multiple account support
- Automatic Java runtime management
- Extensive launcher customization
- Cross-platform support
- Modular and maintainable architecture

These features will be implemented gradually as the project evolves.

---

## 7. What does the project explicitly not intend to be?

Aincrad Launcher is not intended to be a cracked or piracy-oriented Minecraft launcher.

The project will not attempt to bypass Minecraft ownership requirements, authentication systems, or licensing restrictions.

All features should respect the licenses, terms, and intellectual property of Mojang, Microsoft, mod developers, and other third parties.

The project aims to remain completely legitimate and transparent.

---

## 8. What features are envisioned for the final product?

Some of the features currently envisioned include:

- Microsoft account authentication
- Multiple account support
- Minecraft version management
- Instance management
- Profiles
- Mod management
- Modpack support
- Server management and shortcuts
- Automatic Java runtime detection
- Automatic Java runtime installation when necessary
- Launcher updates
- Game version updates
- Customizable launcher interface
- Configurable memory and JVM settings
- Cross-platform support

This list is expected to evolve as the project grows.

---

## 9. What are the project's principles?

The main principles of Aincrad Launcher are:

### Security

User credentials, authentication tokens, downloaded files, and external integrations must be handled securely.

### Modularity

The architecture should allow individual components to evolve without unnecessarily affecting the rest of the system.

### Transparency

Important technical decisions should be documented and understandable.

### Open Source

The project should remain open source and allow users to understand how the launcher works.

### Customization

Users should have control over both the launcher experience and their Minecraft instances.

### Simplicity

Complexity should only be introduced when there is a real reason for it.

---

## 10. What are the main constraints?

The project must:

- Respect Mojang and Microsoft licenses and usage guidelines
- Avoid illegally redistributing proprietary Minecraft files
- Use legitimate authentication mechanisms
- Respect third-party licenses
- Support different operating systems
- Avoid storing sensitive user information insecurely

Technical decisions should always take these constraints into consideration.

---

## 11. Which platforms should be supported?

The long-term goal is to support:

- Windows
- macOS
- Linux

Support will be implemented progressively.

The first development target will be **macOS**, since it is the primary development environment for the project.

Cross-platform support should still be considered during architectural decisions from the beginning.

---

## 12. What should the ideal user experience look like?

The launcher should provide a modern, responsive, and enjoyable user experience.

Users should be able to customize both the appearance and behavior of the launcher while keeping common actions simple.

The ideal experience should allow a user to open the launcher, select an instance or profile, and start playing with minimal friction.

Advanced options should be available without making the basic experience unnecessarily complicated.

---

## 13. What defines success for the first usable version?

The first usable version does not need to contain every planned feature.

A successful initial version should provide functionality comparable to the basic experience of the official Minecraft Launcher.

At minimum, the launcher should eventually be capable of:

- Authenticating a legitimate Minecraft account
- Detecting or managing the required Java runtime
- Installing a Minecraft version
- Launching Minecraft
- Managing basic game configuration

The first implementation will target macOS, with Windows and Linux support added progressively.

---

The technical objective of Aincrad Launcher is to serve as a practical environment for studying advanced software development and software engineering concepts.

---

## 15. What is the development philosophy?

The project follows a few core development principles:

### Start simple

The first implementation of a feature should solve the current problem without unnecessary abstraction.

### Evolve gradually

Complexity should be introduced as real requirements appear.

### Understand before abstracting

Patterns, abstractions, and architectural layers should exist because they solve an identified problem, not simply because they are considered best practices.

### Enjoy the process

Aincrad Launcher is a long-term learning project. Learning, experimentation, mistakes, and refactoring are expected parts of its development.

### Documentation is part of development

Documentation is considered a fundamental part of the project.

Important decisions, architecture changes, discoveries, and project direction should be documented alongside the source code.

The repository should contain enough context for another developer — or an AI assistant — to understand the project without depending on previous conversations or undocumented knowledge.

---

## 16. How should the project evolve?

Aincrad Launcher is intended to become an open-source project.

Development will initially be driven by personal learning and experimentation, but the architecture and documentation should allow the project to grow over time.

If the project reaches sufficient maturity, external contributions may eventually be welcomed.

The project should evolve incrementally:

1. Build a functional core.
2. Make the core reliable and well tested.
3. Build the desktop application around it.
4. Improve the user experience.
5. Introduce advanced Minecraft management features.
6. Expand platform support.
7. Prepare the project for broader community usage.

The exact direction may change as new technical challenges and ideas emerge.
